# Store API operations

## Run locally

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e '.[dev]'
# Filesystem backend: isolated experiments only
STORAGE_BACKEND=filesystem FILESYSTEM_STORAGE_PATH=./storage dark-store-api
# Against a real Cluster, provide an endpoint document (see architecture.md)
STORAGE_ENDPOINTS_FILE=./storage-endpoints.json dark-store-api
```

```bash
curl -s --data-binary @file.xml http://localhost:8003/v1/store     # -> {"cid": ...}
CID=REPLACE_WITH_RETURNED_CID
curl -s "http://localhost:8003/v1/status/$CID"
curl -s "http://localhost:8003/v1/retrieve/$CID"
```

The filesystem backend uses a pseudo-CID and is not a supported architecture.

## In a deployment

- Generated by the deployer per storage access group; the Minter points
  `METADATA_STORE_API_URL` at it, the Resolver at a read-only instance.
- Probe: `/health/live` (process), `/health/read`, `/health/write`. Through the
  deployer: `./deploy.sh verify --deployment ID`.
- Pin observations and coverage across nodes: `./deploy.sh pins coverage|verify`.
- Logs: `./deploy.sh logs --deployment ID --service store-api`
  (set `LOG_LEVEL=DEBUG` through `overrides.settings.store.logging.level` for detail).
- Replacing endpoints after a topology change: `./deploy.sh refresh-store`.

## Troubleshooting

| Symptom | Likely cause | Check |
|---|---|---|
| Fails at start with `storage endpoint file not found` / `must use version 1` | Missing or invalid generated endpoint document | Mount and contents |
| `POST /v1/store` returns `500` `all local Cluster REST endpoints failed` | Cluster peers unreachable or in cooldown (30 s) | Cluster peer logs, `/health/write` |
| `/health/write` `503` with `duplicate_ipfs_peer_ids` | Two Cluster peers share one Kubo identity (bad clone) | Kubo identities per host |
| CID accepted but never `pinned` | Cluster allocation pending or errored | `/v1/status/{cid}`: `queued`/`pinning`/`error` counts |
| `403` on write | `STORE_API_MODE=read_only` | Instance role |
| `422` on ensure | `target_replicas` above `REPLICATION_TARGET_REPLICAS` | Inventory replication target |
| Batch has per-CID `error` | Individual timeouts | Reduce load, `STORE_STATUS_CONCURRENCY` |
